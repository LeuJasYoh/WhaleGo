# PCCtrl × ZCode 电脑操控研究 —— 协作简报

## 0. 项目背景（所有成员必读）

用户（本机 Windows）有一个私有项目 **PCCtrl**：
- 两个 Docker 容器：一个托管机器人账号，一个运行 AstrBot（模型/插件宿主）。
- 目标：在 AstrBot 侧通过**插件 + MCP 等协议**，让模型在容器内 call 一个工具；
  真正**接收 call 并在 Windows 上执行鼠标/键盘/截图等操作**的程序，运行在用户的 Windows 主机上。
- 未定技术栈：Windows 端服务语言/框架未定，因此本阶段只做**学习与参考**，不写实现代码。

**本次任务**：通过工作区里的 ZCode 源码（`ZCode-main/`，开源构建快照 + 大量设计文档），
研究 ZCode 的 **Computer Use（CUA）/ 电脑操控** 是如何实现的，产出一份可供人类阅读、
也可供后续开发智能体直接接手的**中文 Markdown 研究报告**。

**关键事实（先知道，避免误判）**：
- 本仓库是 ZCode 的**开源构建**：`packages/zcode-cua/` 是"API-compatible placeholder"，
  真正的 CUA 原生运行时不在此仓库（闭源/私有构建）；但 `docs/cua/**` 有大量**真实设计规格**，
  `packages/services/src/cua-permission-broker/*.ts`、`apps/zcode-cli/packages/node-repl-host/**`、
  `apps/zcode-cli/packages/zcode-cua-plugin/**`（SKILL/docs/SDK 脚本）以及
  `apps/zcode-cli/packages/browser-use-plugin/**`、`packages/desktop/src/main/browserView/**`
  是**真实源码**。因此证据必须区分：
  - 【代码】= 仓库内可运行/可编译的真实源码
  - 【规格】= docs 下的设计规格（真实产品文档，但非本快照可执行代码）
  - 【契约】= 占位包/类型定义里的 API 契约
  - 【推断】= 基于以上材料的合理推论，必须显式标注
- 模型**并不直接看到**一堆 `mcp__computer-use__*` 工具：2026-08 之后 CUA 收敛到 shared
  `node_repl` 的单一 `js` 工具，Worker 内注入 `agent.computerUse` SDK（见
  `docs/cua-permission-broker/zcode-cua-permission-broker.md` 开头）。这个设计决策本身是重点。

### 笔记文件统一格式（中文 Markdown）

```markdown
# <主题>

> 研究范围 / 阅读材料清单 / 核实基线（例：ZCode-main @ 2026-10 快照）

## 0. 结论速览（给主报告直接可用的 5-10 条）
## 1. …（按主题分节，每节：结论 → 关键机制 → 证据）
## 2. …
## N. 对本项目（PCCtrl / Windows MCP 服务）的可复用结论与坑
## 证据索引（文件:行号 列表，含一句话说明）
```

### 证据标准（硬要求）
1. **先读后写**：每个结论必须来自你实际读过的文档/代码；引用格式 `ZCode-main/docs/xxx.md:123-130`
   或 `ZCode-main/packages/....ts:45`（相对工作区根路径）。
2. 关键结论附 1-2 句**原文摘录**（英文/中文原文均可，用引用块），便于 Lead 复核。
3. 区分【代码】【规格】【契约】【推断】；未找到证据的地方写"未找到/未证实"，不要编。
4. 数字、工具名、协议字段名必须逐字核对；宁可少写，不可错写。
5. 笔记要"密"：以信息密度换篇幅，目标 250-450 行/篇；避免空话。

### 重点回答的问题（各分题按需裁剪）
- 模型看到/调用的准确工具面是什么（名字、参数、返回、错误、图片如何返回）？
- 调用链每一跳跑在哪个进程/哪台机器上，用什么协议/传输，谁认证谁？
- 截图/观察（frame、AX 树、坐标、DPI、窗口/App 定位）怎么实现与约束？
- 输入动作（点击/输入/滚动/拖拽/按键）在 Windows 上具体怎么派发、怎么校验、失败语义？
- 权限、安全边界（TCC/Token/fail-closed/防混淆代理/kill switch）如何设计？
- 生命周期/可靠性（懒启动、健康检查、恢复、超时、孤儿清理、多会话）如何设计？
- MCP/node_repl 的工程取舍（单 js 工具 vs 多工具、stdio vs streamable HTTP、结果预算、图片）？
- 哪些经验可直接迁移到"容器内 AstrBot → Windows 本机执行器"？哪些不能？
